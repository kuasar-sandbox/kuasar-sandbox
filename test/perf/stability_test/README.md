# OpenClaw Long-Term Stability Test

This test runs multiple OpenClaw sandboxes for an extended period while continuously sending chat requests and monitoring sandbox memory usage.

The goal is to validate long-term sandbox stability under a sustained workload and detect issues such as:

- Sandbox or Cloud Hypervisor process failure
- OpenClaw gateway failure
- Connector allocation problems
- Repeated chat request failures
- Significant RSS growth that may indicate a possible memory leak

## Prerequisites

Before starting the test, the local machine must already have a working Kuasar deployment.

The required Kuasar components include:

- `node-ctl`
- `connector-ctl`
- `cache-ctl`
- `store-ctl`
- `manifest-ctl`
- `flatten-ctl`

The related Kuasar services must already be configured and running.

You must also have an LLM endpoint that is either:

- deployed locally, or
- reachable from the test machine

The LLM endpoint is configured through `LLM_URL` in `config.env`.

Other required tools include:

- Docker
- Python 3
- `sudo`
- `curl`
- `jq`
- `socat`

The Python environment must contain the dependencies required by the test scripts, including the E2B SDK and Hugging Face `datasets`.

## Files

The test directory should contain at least:

```text
.
├── start_stability_test.sh
├── config.env
├── prompts.jsonl
├── download_prompts.py
└── README.md
```

`prompts.jsonl` is generated by `python3 download_prompts.py` and should not be created manually.

## Configuration

Each user should maintain their own `config.env`.

Example:

```bash
FLATTEN_CTL="/path/to/flatten-ctl"
MANIFEST_CTL="/path/to/manifest-ctl"
MANIFEST_CONFIG="/path/to/manifest.yaml"

E2B_API_URL="http://..."
E2B_API_KEY="..."
E2B_SANDBOX_URL="http://..."

MANIFEST_KEY="..."
ENCRYPTION_KEY="..."

LLM_URL="host:port"
LLM_API_KEY=""

CONNECTOR_CTL="/path/to/connector-ctl"
CONNECTOR_CONFIG="/path/to/switch.conf"
```

Do not commit real API keys, manifest keys, encryption keys, or other secrets to Git.

The connector configuration referenced by `CONNECTOR_CONFIG` must provide the values required by the test, including:

```bash
FLOATING_IP_BASE=...
MGMT_NETNS=...
MGMT_ADDRS=...
```

The startup script checks that these values are present before continuing.

## Download Test Prompts

The workload uses prompts from the CodeAlpaca dataset.

Install the dataset dependency if needed:

```bash
pip install datasets
```

Then run:

```bash
python3 download_prompts.py
```

This downloads `HuggingFaceH4/CodeAlpaca_20K` and creates:

```text
prompts.jsonl
```

in the same directory as `download_prompts.py`.

The stability test will refuse to start if `prompts.jsonl` is missing.

## Run the Test

Start the test as your normal user:

```bash
./start_stability_test.sh
```

The script builds an OpenClaw image, exports it through `flatten-ctl`, stores the manifest, creates the configured number of sandboxes, attaches them to the connector network, and waits for the OpenClaw gateways to become healthy.

The current default test settings are:

```text
Test duration / sandbox timeout: 86400 seconds
Sandbox count:                  5
Chat interval:                  30 seconds
Memory monitor interval:        30 seconds
```

Each chat round sends one request to every sandbox.

The prompt for each request is randomly selected from `prompts.jsonl`.

OpenClaw chat sessions are periodically reset so that individual conversations do not grow indefinitely during the long-running test.

Press `Ctrl-C` to stop the test.

## LLM Connectivity

The test creates a `socat` forwarding path between the sandbox management network and the configured LLM endpoint.

Conceptually:

```text
OpenClaw sandbox
      |
      v
management network :18000
      |
      v
socat
      |
      v
LLM_URL
```

Make sure the configured LLM endpoint is reachable from the host before starting the stability test.

## Memory Monitoring

The script monitors the RSS of the Cloud Hypervisor process associated with each sandbox.

The first observed RSS value becomes that sandbox's baseline.

The current memory-growth heuristic is:

```text
MEM_GROWTH_MB=512
MEM_GROWTH_SAMPLES=10
MONITOR_INTERVAL=30
```

An alert is generated when RSS remains at least 512 MiB above the initial baseline for 10 consecutive monitoring samples.

With a 30-second monitoring interval, the condition must therefore persist for approximately 5 minutes.

This is a heuristic for detecting suspicious memory growth. It does not by itself prove that a true memory leak exists.

## Output

By default, test artifacts are stored under:

```text
~/openclaw_long_term_stability
```

The location can be overridden:

```bash
STABILITY_WORKDIR=/path/to/workdir ./start_stability_test.sh
```

Important output files include:

```text
logs/chat.log
logs/chat_responses.jsonl
logs/memory.csv
logs/alerts.log
results/sandboxes.csv
```

### `memory.csv`

Contains periodic memory samples for each sandbox:

```text
timestamp,sandbox_id,pid,rss_kb,rss_mb,baseline_mb
```

Use this file to inspect long-term RSS trends for individual sandboxes.

### `chat_responses.jsonl`

Contains the prompt and response for successful workload requests.

### `alerts.log`

Contains detected runtime issues, including process disappearance, failed requests, gateway failures, and possible memory-growth alerts.

If an alert is raised, the test also creates an `ALERT` file in the stability work directory.

## Before Starting

Verify the following before running the test:

- Kuasar is deployed and its required services are running.
- `node-ctl`, `connector-ctl`, `cache-ctl`, and `store-ctl` services are available.
- `config.env` contains your own local paths, endpoint addresses, and credentials.
- The connector configuration is valid.
- The LLM endpoint is deployed or reachable.
- Docker is working.
- Required Python packages are installed.
- `prompts.jsonl` has been generated with `download_prompts.py`.
- No existing E2B sandbox or connector allocation will conflict with the test.

Once these prerequisites are satisfied, start the test with:

```bash
./start_stability_test.sh
```
